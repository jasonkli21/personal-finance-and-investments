# Repository maintainability and implementation review

**Date:** 2026-10-03
**Scope:** The implemented repository, including local portfolio/finance workflows, Stage 3 calculations, offline research, and prepared deployment/recovery tooling. This review does not promote a future stage or authorize cloud/provider access.

## Outcome and architecture

The repository remains a React/TypeScript application calling one FastAPI backend. Domain modules own financial rules; routes own HTTP contracts; SQLAlchemy owns persistence; provider and file-store interfaces preserve offline operation. PostgreSQL 16 is the local source of truth. Aurora DSQL has an independent connection and migration path and remains a required, unverified production gate. Private originals are content-addressed local files, with a prepared S3 adapter. The only enabled background work is local PDF preview. Personal-AI extraction and research transport remain disabled.

Contained fixes address confirmed correctness, persistence, concurrency, security, interface and maintainability defects. Applied migrations were not changed, technologies were not replaced, dependencies were not upgraded, and no external service or cloud deployment was activated. Tests use synthetic data. Existing unrelated handoff material was preserved.

## Structural cleanup

- Catalog authoring moved from the import module into the existing securities domain. Imports now consume catalog records, and catalog/quote writes have concrete types instead of `Any`.
- Owned valuation and frozen reports share one accepted-quote selection policy. This removes divergent source/timestamp/tie handling and keeps stale-value disclosures consistent.
- Frontend authentication, revision-bound drafts, upload response handling, CSV header parsing, local dates and stable submission keys now have small cohesive components/helpers. Workspace forms retain edited evidence and its original revision across refetches.
- Backend router registration and lifecycle cleanup are explicit in `app/main.py`. Stage 3 routes use the existing shared session dependency. Recovery imports use ordinary SQLAlchemy imports.
- Related category/split/transfer reads and historical line counts are batched rather than queried once per record.
- Infrastructure tests moved from `scripts/stage4/test_infra_contract.py` to `tests/infra/test_infra_contract.py`; root test, lint, formatting and type commands include that tree. Production source remains under `services/api/app` and `apps/web/src`; tests remain under `services/api/tests`, `apps/web/test`, `apps/web/e2e` and root `tests`.
- CI now runs the isolated PostgreSQL encrypted recovery drill as well as ordinary tests and browser journeys. Alembic's path separator is explicit. Two immutable historical migrations (`0007`, `0015`) are excluded only from formatting, retaining lint and runtime checks.
- Main documentation and working instructions describe delivered later-stage code accurately. Historical release counts remain dated evidence; this report records the newer validation.

## Tests and validation

The broad repository gate was run against a newly initialized, isolated PostgreSQL **16.15** cluster on loopback port **55483** and synthetic disposable databases. The unrelated service on port 55432 was not changed. Backend suites that reset schemas ran sequentially; browser tests use their own disposable database. Temporary recovery databases are created and cleaned by the recovery drill.

```sh
# From the repository root; requires the project Node/pnpm/uv toolchain.
pnpm api:generate
TEST_DATABASE_URL='postgresql+psycopg://<local-role>@127.0.0.1:<port>/<disposable-test-db>' \
STAGE4_RECOVERY_TEST_ADMIN_URL='postgresql+psycopg://<local-role>@127.0.0.1:<port>/postgres' \
  pnpm check

E2E_DISPOSABLE_DATABASE=1 \
E2E_DATABASE_URL='postgresql+psycopg://<local-role>@127.0.0.1:<port>/<disposable-browser-db>' \
  pnpm test:e2e
```

- `pnpm api:generate` refreshed FastAPI OpenAPI and generated TypeScript schemas; `pnpm api:check` passed.
- Final combined `pnpm check` passed after all code changes: web ESLint/Prettier/TypeScript, Python Ruff lint/format and strict mypy (**106 files**), **22 Vitest tests**, **5 infrastructure contract tests**, **275 pytest tests with 15 real-DSQL tests skipped**, and the production web build. The earlier aggregate run passed 273 tests; two research precision regressions were added and the entire gate repeated.
- PostgreSQL tests include fresh and populated Alembic upgrades, schema/NUMERIC/JSONB/foreign-key behavior, import/publication/revision concurrency, and encrypted export/verify/isolated restore including interruption, tampering and repeat idempotency.
- Six new advanced PostgreSQL workflows explicitly test a non-UTC session: deposit-neutral performance, tax publication/adjustment idempotency, read-only two-lot sale comparison, liquidity planning, frozen research/report/note lineage and exact fact read/idempotency conflicts for values differing only in their final supported digit.
- Playwright: **7 passed** against a fresh synthetic PostgreSQL database with all **18 migrations**. Cases cover the Stage 1 portfolio journey, transaction/tax stale draft fences, session/logout races, 201-row pagination, issuer selection reset and captured-account publication. Web checks were repeated after correcting a synthetic tax fixture to submit an actual field change.
- `git diff --check` passed. File discovery confirms tests are in dedicated trees and the moved infrastructure-test reference is updated.
- `uv build --directory services/api --out-dir /private/tmp/personal-finance-review-dist` built the backend source distribution and wheel. The initial offline attempt lacked cached Hatchling; the normal build resolved its declared build dependency. Package inspection includes all 71 Python source modules and excludes tests; imports of the unpacked wheel's app, authentication and research modules passed from outside the checkout. - Docker and Terraform executables are unavailable in this environment, so no fresh container build, `terraform fmt`/`validate`/plan or cloud startup test was run. Static topology/guardrail tests passed; they do not parse HCL or establish applied AWS policy. No dependency versions or provider pricing claims were changed.
- No real Aurora DSQL, AWS, SEC/IR, personal-AI or personal financial data was used. The real DSQL skips and hosted gates remain explicit.
