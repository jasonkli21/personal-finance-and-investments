## S2.1 local slice

`POST /v1/imports/documents/positions/preview` accepts one bounded PDF and account/date/source/revision metadata, stores the original privately, and returns a durable job. The local in-process worker extracts a supported text-layer holdings table in a resource-limited child process and stages normalized rows through the Stage 1 position import review. `GET /v1/jobs/{id}` exposes safe progress/result state; `POST /v1/jobs/{id}/cancel` cancels pending work or requests cancellation before review publication. The browser preserves the active job ID across reloads. Review corrections, cancellation, and publication use the existing `/v1/imports/{id}` workflow. `GET /v1/documents/{id}` returns safe metadata and parser diagnostics; `GET /v1/files/{id}/preview` serves a linked PDF with private/no-store headers.

Supported parser layout: a single holdings table with recognized identifier/name, quantity, price/value, and optional currency columns, with cells separated by repeated spaces or pipes. Evidence uses page and line numbers. Quantity × price mismatches, absent prices/values, absent/mismatched statement dates, assumed account currency, and unparsed lines remain warnings/review rows. A PDF without an extractable text layer or with an unsupported table must use the existing CSV/manual workflow. This is not OCR and does not infer trades, cost basis, or missing identifiers.

The checked-in example is wholly synthetic: [`fixtures/stage-2/synthetic-brokerage-statement.pdf`](../fixtures/stage-2/synthetic-brokerage-statement.pdf), with [`expected-brokerage-extraction.json`](../fixtures/stage-2/expected-brokerage-extraction.json). The parser's dependency is pypdf 6.x; its child process receives only the configured page bound (and the Windows system-root variable when needed), not the API process environment. Original files stay outside SQL and static/public assets. Private file access currently assumes the local single-user deployment boundary. Do not expose these routes in an unauthenticated hosted deployment; Stage 4 auth/storage controls are not implemented.

Local job defaults are `JOB_WORKER_ENABLED=true`, `JOB_POLL_INTERVAL_SECONDS=1`, `JOB_LEASE_SECONDS=30`, and `JOB_MAX_ATTEMPTS=3`. The lease must exceed `PDF_PARSER_TIMEOUT_SECONDS`; retries use a capped exponential delay. Disable the worker only when the PDF preview route should reject requests.

## Verification state

The generated OpenAPI JSON and TypeScript schema include the S2.1, S2.3, S2.4, and S2.6 routes and contracts. On 2026-10-02, the final API suite passed **106 tests, with 9 skipped**, using synthetic SQLite fixtures and a disposable PostgreSQL 16.15 cluster. This includes fresh and populated migration paths, transaction concurrency, split replacement, provider-update revision/reconciliation, required-field validation, unclassified summary coverage, cancellation/reupload, actual PDF processing, and lease loss during staging. Web tests passed (9 tests), the web build/type checker and generated API check passed, and Python Ruff and mypy passed. Live DSQL and browser journeys remain unverified. Repository-wide web lint still reports four pre-existing `react-hooks/set-state-in-effect` errors; repository-wide Python formatting still flags the applied `0007` migration, which was left unchanged.

Local migration `0011_transaction_description` repairs the description column omitted from PostgreSQL migration `0008`, backfills existing rows from their raw description, and restores the required non-null contract. The independent DSQL `0008` plan already creates that column; its migration plan remains unchanged and structurally tested. Apply the local repair with `uv run --directory services/api --locked alembic upgrade head`. Original applied migrations were not edited.

PDF parsing keeps parent secrets out of the child process. Linux applies the address-space limit; macOS does not support that limit, so only CPU, wall-clock, file/input, page and text bounds are enforced there. Cancelled PDF reviews can be reprocessed with either a reused or new upload key, preserving the original and prior audit record. Abandoned cancellation recovery is bounded to 100 jobs per polling pass. Monthly summaries visibly label unresolved classifications and refresh after spending edits; unresolved transaction types do not change net-worth completeness. Remaining parser benchmarks, broader browser journeys, full worker restart acceptance, and the live DSQL path remain unverified. Do not treat the synthetic expected JSON as a benchmark result.
