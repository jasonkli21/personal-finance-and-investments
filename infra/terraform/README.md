# Prepared GCP / Neon deployment

No resources were applied. This replaces the predecessor target under ADR 0002; do not reuse older state against this configuration. Neon project/branch/roles are operator-managed, outside Terraform. Use a dedicated GCP project and explicitly approved billing/retention policy.

1. Copy terraform.tfvars.example to the ignored terraform.tfvars and fill actual IDs/origin/OIDC owner settings. Bootstrap with enable_runtime=false. Use operator ADC; no credential files in the repo.
2. Run terraform init, fmt -check, validate and test (mocked provider plans). Commit the provider lockfile. Review a saved plan before applying. Bucket/secret prevent_destroy and runtime deletion protection intentionally require explicit exit decisions. No secret payloads enter Terraform.
3. After approved bootstrap, add DATABASE_URL, OIDC client secret and session signing key versions through Secret Manager. The database URL is a runtime Neon role with verified TLS. Use a separate direct MIGRATION_DATABASE_URL for Alembic/operator migration; do not give it to the runtime.
4. Build/push the exact-source Dockerfile image to the output image_repository, capture its immutable sha256 digest, and set api_image_digest plus numeric secret_versions. Review a new saved plan with enable_runtime=true. No mutable tags/latest secrets.
5. Run Alembic head with direct Neon credentials and explicitly bind the owner principal. Validate disposable Neon, then deploy only the reviewed runtime plan. API scales 0–2 instances, concurrency 8, pool 5/no overflow; worker has one 300-second task and a bounded claim loop. Multiple job executions can overlap, so rehearse backlog/trigger failures and review the connection/cost envelope.
6. From infra/terraform, `terraform output -json firebase_config > firebase.json`; `pnpm --dir ../.. build:web`; `firebase deploy --project <actual-project> --config firebase.json --only hosting`. The generated file is ignored. It routes /api/** to the matched Cloud Run service before SPA fallback and pins its revision. The public build directory is ../../apps/web/dist relative to that generated config. Custom-domain/DNS verification remains an operator step.
7. Run the Stage 4 synthetic HTTPS/OIDC/private-GCS/jobs/recovery and cost gates before any personal data. Firebase requires publicly invokable Cloud Run; backend authorization protects all finance routes, including direct service access. Bucket/jobs remain private. Runtime access is limited to create/read private objects and three pinned secrets; API alone may execute the worker.

Terraform provider-schema validation is offline evidence only. Plan/apply requires target ADC/resources and review; it is not part of pnpm check. Budgets use actual billing contacts and are alerts, not spending caps. No scheduler or new queue is installed. The dedicated project’s default log bucket retains 30 days; managed Cloud Run request URL logs are excluded from its default sink. Keep redacted app logs and review custom/organization sinks and Firebase query handling before production. See current Stage 4 runbooks for promotion, pause/rollback and retained-resource exit inventory.
